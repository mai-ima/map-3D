## 1. 最初の仕様（2026-08-28）

33 節からなる開発仕様を受け取っている。要点のうち、
**作業中に忘れると取り返しがつかないもの**を挙げる。
全体構成は `docs/architecture.md` に落とし込んである。

### データの優先順位（第 2 節）

実在する場所について、建物や道路を勝手に生成させない。

```
1. 実際の GIS データ
2. OpenStreetMap
3. PLATEAU
4. 国土地理院
5. その他、利用条件を満たす公開データ
6. AI 生成データは「不足する視覚的アセットの補完」のみ
```

「実在する東京駅を、東京駅っぽく生成させてはいけない」と明記されている。

### AI 生成アセットの用途（第 18 節）

使ってよい対象は、木・街灯・標識・ベンチ・自動車・自転車・小物・
仮想的な装飾など、**位置が地図の正確さに関わらないもの**に限る。
形式は glTF / GLB、PBR マテリアル。

なお現状、AI 生成の 3D アセットは 1 つも使っていない。
街路樹・街灯・ベンチ・信号は OSM の実在位置に、
公開されている設計基準の寸法で組み立てている
（`packages/gis/src/street-furniture-geometry.ts`）。

### 禁止事項（第 29 節）

- Google Maps のコードやデータをコピーする
- Google の非公開 API を解析して利用する
- Google Maps の 3D データをスクレイピングする
- Google の UI をそのままコピーする
- 実在建物を AI で勝手に捏造する
- ライセンス不明の 3D モデルを利用する
- API キーを Git に保存する
- 日本全国の巨大データを初回ロードする

### 実装前の手順（第 28 節）

コードを書く前に、リポジトリ構造・ライブラリ・データ形式・ライセンス・
API 仕様を確認し、アーキテクチャを設計してから実装する。

> 不明な仕様を勝手に想像して実装しない。公式ドキュメントを優先する。

Cesium / PLATEAU / OpenStreetMap / Valhalla / PostGIS については、
**現在の公式仕様を確認してから**実装する。

### AI は地図を直接操作しない（第 16 節）

自然言語での操作は必ず Tool Calling を経由する。
`search_place` / `search_nearby` / `calculate_route` /
`get_building_info` / `get_map_context` / `set_camera` /
`highlight_location` など。

### ライセンス（第 21 節）

OpenStreetMap・PLATEAU・国土地理院それぞれの条件を確認し、
表示を UI に実装する。**ライセンスが不明なものは使用しない。**
→ `docs/licenses.md`、`packages/shared/src/attribution.ts`

### 座標系（第 25 節）

WGS84 / JGD2011 / 平面直角座標系を正しく扱い、変換は共通モジュールに置く。
→ `packages/shared/src/coords.ts`

### 品質目標（第 32 節）

> 「Google Maps を開いている」という感覚ではなく、
> 「日本の都市を 3D ゲーム世界として探索している」という感覚

### 進め方（第 27 節・第 33 節）

Phase 1（3D 都市の表示）から順に、**各 Phase が実際に動作することを
確認しながら**進める。一度に巨大なコードを書かない。

補足として「iPhone の場合は iPhone 最適化（iPhone 17 想定なので
クオリティ低下は不要）」「検索に関してはどんどんして貰って構いません」
「vercel 動作可能に」「報告など全て日本語で途中報告も」。

## 2. 会話の作法として繰り返し受けた指示

同じ指示を何度も受けている。**それだけ守れていなかったということ。**

| 指示 | 受けた回数 | 記録先 |
|---|---:|---|
| 必ず日本語で（返事・途中報告・コミット） | 6 回 | CLAUDE.md §1 |
| 中断せず最後まで続ける | 6 回 | CLAUDE.md §1 |
| 絵文字を使わない（SVG で代替） | 1 回 | CLAUDE.md §1 |
| URL は特別なものがあるときだけ | 3 回 | CLAUDE.md §1 |
| Vercel の MCP は読み取りのみ | 1 回 | CLAUDE.md §2 |
| 考えるだけでなく多く調べる | 4 回 | CLAUDE.md §2 |

「考えるだけでなく多く調べてください」「外部サイト複数を参考に」
「最新情報とかも調べて」「類似事例や Web ゲームの技術調べて応用して構わない」
と、調査を促す指示が繰り返されている。

## 4. 応えきれていないもの

正直に書く。

- **Valhalla の車線案内・方面案内**。既定の経路エンジンは Valhalla だが、
  応答の形を実データで確認できていない（公開デモが 503 で到達できなかった）。
  推測で解釈すると誤った矢印を出すので足していない。
  いまは `ROUTING_ENGINE=osrm` のときだけ車線案内が出る
- **実機での確認**。iPhone 17 の実機は手元に無く、
  この作業環境のブラウザは外部へ出られない。
  地形・ベースマップ・建物タイルの見た目は目で見られていない
  （`npm run measure:smoke` で「画面が壊れないこと」までは確認している）
- **AI プロバイダの実応答**。鍵が要るので擬似応答でしか検証していない
- **浜松の街路樹**。OSM に `natural=tree` が 0 本、PLATEAU にも植生モデルが無い。
  方針により「出さない」が正解なので、出していない

## 5. この記録の更新の仕方

新しい依頼を受けたら、**作業を始める前に**この台帳へ 1 行足す。
対応したらコミットの短縮ハッシュを書き込む。

恒久的な方針（毎回守るもの）を受け取ったときは、
台帳に書くだけでなく **`CLAUDE.md` にも写す**。
CLAUDE.md はセッションをまたいで必ず読み込まれるが、
このファイルは読みに行かないと読まれない。
