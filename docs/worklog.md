## いま取り組んでいること

### 道・木・車道・車線・信号・線路が出ていない欠陥の解消

利用者からの指摘: 「道もダメ、木も車道も車線も信号もダメ、線路などもない」
「速度制限なども表示されない」

**原因は 2 つあった。**

1. OSM XML パーサがノードを 1 件も返していなかった（`docs/pitfalls.md` 参照）。
   信号・横断歩道・街路樹はすべてノードなので、丸ごと落ちていた。→ 修正済み
2. 道路・車線・線路を描く仕組みがそもそも無かった。→ 記述層まで作成、描画側は未着手

**進んでいるところ:**

- [x] OSM XML パーサの修正（`packages/gis/src/osm-api.ts`）
- [x] 道路の記述層（`packages/gis/src/road-geometry.ts`）
      種別の判定、車線数・幅・速度制限の決定、
      舗装・区画線・中央線・横断歩道・線路・信号の形を組み立てる。
      Cesium に依存しない純粋な関数。テスト 16 件。
- [x] `/api/roads` エンドポイント。Overpass が落ちていたら OSM 本体 API に切り替える
- [x] `SceneShape` を Cesium で描くレンダラ（`scene-renderer.ts`）
      幅 0.5m 以上は面（`CorridorGeometry` + `GroundPrimitive`）、
      未満は線（`GroundPolylineGeometry`）。立体は `PolylineVolumeGeometry` と
      `BoxGeometry`。同じ描き方のものは 1 つの Primitive にまとめる
- [x] 地表の高さの格子（`terrain-grid.ts`）。
      100m 格子で取って双線形補間。点ごとに問い合わせると数千件になる
- [x] 速度制限の表示（規制標識を SVG で描く）。
      OSM に `maxspeed` があるときだけ。超過していたら現在速度を赤くする
- [ ] 街路樹が実際に出ることの確認（パーサ修正で取れるようになったはず）
- [ ] 実機で道路・線路・信号が正しい位置に出ることの確認

  （テストでは擬似時計で確認済み。実際の描画までは見ていない）

### まだ検証の網が掛かっていない場所

fuzz と実データの検証は、GIS・描画・ナビ・API・経路解析・AI のツール実行まで当てた。
残っているのは `packages/ai/src/providers`（各社 API の応答解析）と
`packages/map-engine/src/buildings.ts` の LOD 切り替え。
前者は鍵が要るので実応答での確認ができていない。

### 軽量化（部品や精度を下げない方法）

道路の描画負荷は `npx tsx scripts/preprocessing/survey-roads.mts` で測れる。
浜松駅周辺 1km 四方の実測（2026-09）:

| | 形の数 | 頂点の目安 |
|---|---:|---:|
| 当初 | 3,972 | 51,622 |
| 細切れの道をつないだ後 | 3,631 | 50,892 |
| 外側線を幹線だけにした後 | 2,741 | 39,992 |

形 31% 減・頂点 23% 減。どちらも部品も精度も落としていない。
外側線の見直しは、むしろ実態に合わせた修正（住宅街の道に白線は無い）。

- [x] 上空では区画線を描かない（見えないものを描かない）。
      高度 800m を境に切り替える。範囲は同じなので取り直さず、
      手元のデータで組み直すだけ（通信も待ちも要らない）
- [ ] 道路・線路の描画をワーカーへ逃がす
- [ ] タイルの取得順序の見直し（起動時の集中を緩める）

つなぎ処理で減ったのは 8% にとどまった。名前の一致を要求し、
分岐点ではつながないため。**これ以上つなぐと線形が嘘になる**ので広げない。

### いま Cesium に依存しているのは packages/map-engine だけ

```
packages/gis/          OSM/PLATEAU の解釈、寸法の決定    … Cesium なし
packages/shared/       型と「形の記述」(scene.ts)        … Cesium なし

```

Swift へ移すときは `map-engine` を置き換えれば、
寸法の決め方（何を描くか）はそのまま持っていける。

## これまでに片付いたこと（要点だけ）

| 課題 | 対処 | 効果 |
|---|---|---|
| 浜松で建物が二重に描かれる | near/far が同一四分木を返していた。`needsFarTileset` で遠景を作らない | タイル取得が半減 |
| 東京が重い | 端をかすめるだけの区まで開いていた。重なり面積順に上限まで | json 4.3→2.2MB、タイル 3,555→2,571 |
| 高架が重なる・積み上がる | 線路が 1 本ずつ別 way だった。縦につなぐ+横にまとめる+区間ごとに幅を測る | 重なり 110 組→9 組 |
| 高架に段差 | 高さの基準を桁下から路面へ | 1.2m の段が消えた |
| 橋が浮く | `layer=1` が水路との上下関係だった | 浜松の道路橋 56 本すべてが該当 |
| 建物のスタイルが当たらない | `defined()` はスタイル式に無い / `${['bldg:usage']}` は黙って undefined | 遠景の色が初めて付いた |
| 3D モデルがチカチカする | 「先に消してから作る」を「作ってから消す」へ（建物・高架・街路樹） | 空白の数秒が無くなった |
| 信号・街路樹が出ない | OSM XML パーサの先読みが成立せずノードが 0 件 | ノードが取れるようになった |
| Cesium アセットが大きい | GoogleEarth/I3S/Splats/zip/waterNormals を配布から除外 | 5.9→4.7MB |
| 柱が多すぎる | 距離に応じて 2 の冪で間引く | 柱 38% 削減 |
| 水路判定が遅い | 矩形の早期棄却 + WeakMap キャッシュ | 154ms→49ms |
| 高架でない所が高架になる | `layer>0` だけで判定していた。トンネル除外 + 長さ条件 + 歩行者用は bridge 必須 | 東京で誤り 254 本→0 |
| 縮小すると日本地図が消える | 地理院タイルに z=0/1 が無いのに `minimumLevel` 未指定だった | 引いても地球に絵が貼られる |
| 高架でない所が高架になる | `layer>0` だけで判定していた。トンネル除外 + 長さ条件 + 歩行者用は bridge 必須 | 東京で誤り 254 本→0 |
| 読み込み中に操作すると落ちる | 破棄後の scene に触っていた。`liveScene()` で毎回確かめる | 例外が出なくなった |
| 極端なタグでブラウザが固まる | `tracks=1000000000` で線路を 10 億本組もうとしていた | 上限を掛けた |
| 検索結果が入力と食い違う | 通信中に入力が変わると古い結果が新しい結果を上書き | 古い検索を捨てる |
| 引数なしの API 要求が通る | `Number(null)` が 0 なので「大西洋の座標」として受けていた | 検証を shared に集約 |
| 線路や道がどこにも描かれない | 地表側と高架側で判定が食い違っていた | 東京で 136 本が復活 |
| 経路エンジンの応答欠けで英語の内部エラーが出る | 必須のはずの配列が undefined で来る 7 通りを塞ぐ | 日本語の案内に統一 |
| 複数レグの経路が日本から飛ぶ | polyline の文字列を連結していた（差分符号なので不正） | 座標から符号化し直す |
| 現在時刻に追従すると発熱する | 時計を進めると requestRenderMode が無効になっていた | 描画 60/秒→1/分 |
| 追従中に夜になっても昼のまま | 夜の補正と星空を最初の 1 回しか適用していなかった | 日没で切り替わる |
| AI が地図を壊せる | 俯角 -400 度・高度 0・負の半径がそのまま通っていた | 数値も範囲を検証 |

### 正直に書いておく

- 500m 格子への丸めは、**一方向に移動し続ける場合は取り直しの回数が変わらない。**
  同じ場所を行き来するときにだけ効く。
- Cesium 本体の JS は生 3.9MB だが gzip で 1.0MB。
  ダウンロード量は妥当で、重さの主因は実行時にある。
